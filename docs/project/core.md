# Metis 核心设计

Metis 面向需要在 Agent 和业务流程中使用专用模型的开发者，提供排序、选择和分类任务的后训练、评测与调用工具。

工具包通过配置和适配器复用固定任务的训练流程。模型直接返回分数、类别或候选 ID；这里用 SystemOne 表示这种职责。低延迟收益需要实测。

产品与代号为 **Metis**，安装包、Python import 和 CLI 使用 `metis`。当前能力见[项目状态](status.md)。

## 架构 v1.0

v1.0 固定当前计算架构：结构化候选输入经 pairs 或 dense tree 编译，由 Qwen3 Base + 独立 MLP ScoreHead 输出候选分数，再由任务决策返回候选 ID。Qwen3 Reranker yes/no 保留为另一种适配器，两者不是串联模型。

此处的 v1.0 表示架构基线，不表示软件包已发布 1.0.0。模块整理、测试、数据质量、评测与校准可围绕该基线完善；新增候选交互网络、更换读出或改变候选可见性属于后续架构变更。强化学习、分布式执行与稀疏后端分别是训练方法、运行方式和算子实现的扩展，均不计入 v1.0 已实现能力。

## 模型与训练的分层

以下划分指导扩展，通用 task/objective/backend 注册尚未实现。

| 层次 | 职责 |
|---|---|
| Task / Objective | 定义标签、采样、损失、指标与决策策略，按任务选择 BCE、CE 或排序目标 |
| Backbone / Readout / Layout | 适配基座、读出和输入布局；支持独立打分或候选间交互 |
| Runtime / Backend | 复用 Trainer、PEFT、batching 与 attention 算子，管理恢复和导出 |

Qwen Base + 独立 ScoreHead 是主要适配路径；reranker yes/no 是另一种读出。监督后训练按任务定义目标，保留判别式训练方式。

Tree 使用共享前缀、隔离候选与一致的逻辑位置。要等价于 `prefix + candidate`，分支位置通常从前缀长度续编。候选交互是否合适取决于任务；同输入下 pairs/tree 的近似等价需要分数、梯度和换序检查。

当前 tree 是 dense mask 参考实现，仅完成小规模正确性预检。训练质量、吞吐、显存与稀疏加速分别需要实验验证。

RL 是后续方向，可以复用现有评分模型，但需要新增动作分布、采样、reward、交互记录及优化目标。确定性 TopK 本身没有策略采样，不能直接用于策略梯度训练。候选策略的接入边界见[框架设计](../architecture/framework.md#强化学习接入设计)。

## 在 Agent 中的分工

通用 LLM 负责规划、生成和开放式推理；Workflow/Harness 负责调用、状态、环境交互与记录；Metis 模型负责可独立评估和部署的固定任务。Memory、Skills 与 MCP 提供资源、过程说明和接入方式。

训练产物通过函数或服务接入下游流程。工具包先验证模型与调用，再由业务流程评估实际收益。

## 实验与来源

Cookbook 固定数据划分、候选、标签语义和评测协议，实际更新参数并导出可重载产物。用 dev 选择模型，固定后评测 test；软件检查、真实训练和模型质量分别记录。

NFCorpus 是首个 cookbook。公开源码不分发数据、模型权重、原始报告、服务器资料或第三方课件；教学与方法来源见[致谢](../../ACKNOWLEDGEMENTS.md)。
